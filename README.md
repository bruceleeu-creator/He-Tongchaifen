# 合同拆分（He-Tongchaifen）— 年度财税顾问项目拆分工作台

> 将年度财税顾问合同与服务计划，自动拆解为**可执行、可跟进、可导入**的项目任务主表。
> 仓库地址：https://github.com/bruceleeu-creator/He-Tongchaifen.git

---

## 一、产品介绍

### 1.1 解决什么问题

财税顾问机构签订年度服务合同后，需要把合同中散落的条款（服务内容、付款节点、驻场安排、响应时效、验收标准等）人工梳理成项目任务表，再分派给团队跟进。这个过程存在三个痛点：

1. **遗漏**：合同执行条款（如"每季度现场服务五个工作日""四十八小时内响应"）容易被忽略，未转化为任务；
2. **无依据**：任务表和合同原文脱节，说不清每条任务"凭什么要做"；
3. **低效**：一份合同人工拆表往往需要数小时，且质量依赖个人经验。

本应用以**合同原文理解为核心**，通过"深度读取 → 识别摘要 → 动态追问 → 二次拆分 → 报告校验 → 交付成果 → 导出"的全流程，把上述工作压缩到分钟级，并保证每条任务都标注合同条款来源。

### 1.2 核心特性

- **两种解析模式**：规则解析（无需 API Key，开箱即用）+ LLM 增强（配置 DeepSeek/通义千问/OpenAI 后自动升级，AI 失败自动回退规则模式，流程永不中断）
- **9 步全流程自动化**：一键跑完"合同识别 → 计划识别 → 交叉核验 → 动态追问 → 任务拆分 → 颗粒度检查 → 待确认清单 → 风险提示 → 报告校验"，支持暂停/恢复/跳过/重试
- **18 字段任务主表**：行业标准的任务字段体系，逐条标注 AI 提取依据（合同条款来源）
- **9 项报告校验**：导出前自动校验客户一致性、金额识别、日期合规、Mock 污染、核心模块覆盖等，不通过不放行
- **交付成果生成**：按任务/整单生成对应交付文档，支持模板管理与打包下载
- **版本管理**：任务表可保存版本、查看历史、一键回退
- **多格式导出**：CSV（18 字段，可直接导入 Excel/项目工具）、Markdown 报告、完整数据包

### 1.3 技术架构

| 层 | 技术 |
|----|------|
| 前端 | React 18 + Ant Design 5 + Vite + TypeScript + Zustand + axios |
| 后端 | FastAPI + python-docx + httpx + uvicorn |
| AI | OpenAI-compatible 接口（DeepSeek 默认 / 通义千问 / OpenAI 可切换） |
| 存储 | 纯 JSON 文件（无数据库，运行数据与代码分离，便于迁移与备份） |

视觉主题为"顾问账簿"（深墨蓝 × 羊皮纸 × 古金），界面语言为中文。

## 二、功能详述

### 2.1 六大功能模块（页面导航顺序）

| 模块 | 页面 | 功能 |
|------|------|------|
| 资料上传 | `/upload` | 上传 Word 合同与服务计划（可多文件）；文件类型智能推断 + 用户显式选择优先；"AI 全流程分析"一键入口（未上传合同时自动拦截） |
| 识别结果 | `/recognition` | 合同识别摘要（甲乙方、项目名称、费用、期限、驻场、响应时效等）+ 识别依据明细；计划识别 + 合同/计划交叉核验 |
| 澄清追问 | `/clarification` | 根据合同摘要自动生成追问表单，补充 AI 无法从原文确定的事项；回答后参与二次拆分 |
| 任务复核 | `/task-review` | 18 字段可编辑任务主表（行内编辑、弹窗新增、详情抽屉）；颗粒度检查、待确认清单、风险提示；报告校验（9 项规则）；AI 交付成果面板（生成/下载/模板） |
| 版本记录 | `/version-history` | 保存版本、查看版本详情、回退到任意历史版本 |
| 导出 | `/export` | CSV 任务表、Markdown 项目报告、完整数据包导出 |

### 2.2 9 步全流程管线

点击"AI 全流程分析"后，后端按以下顺序自动编排执行（每步状态实时可见）：

| 步骤 | 名称 | 说明 |
|------|------|------|
| 1 | 合同识别 | 深度读取合同原文，提取核心字段 |
| 2 | 计划识别 | 识别年度服务计划（如已上传） |
| 3 | 交叉核验 | 合同与计划交叉核验，识别冲突 |
| 4 | 动态追问 | 根据合同摘要生成追问问题 |
| 5 | 任务拆分 | 基于合同 + 追问回答生成任务主表 |
| 6 | 颗粒度检查 | 检查任务拆分粒度是否合理 |
| 7 | 待确认清单 | 生成待人工确认事项清单 |
| 8 | 风险提示 | 生成风险提示清单 |
| 9 | 报告校验 | 9 项校验规则检查报告质量 |

支持操作：启动 / 暂停 / 恢复 / 跳过某步 / 重试某步 / 重置管线。任一步 LLM 调用失败会自动回退规则解析，不会中断流程。

### 2.3 18 字段任务主表

| # | 字段 | # | 字段 |
|---|------|---|------|
| 1 | 客户名称 | 10 | 客户需提供的资料或配合事项 |
| 2 | 项目名称 | 11 | 当前状态 |
| 3 | 任务名称 | 12 | 延期责任归属 |
| 4 | 服务模块 | 13 | 节点目标/达到效果 |
| 5 | 任务类型 | 14 | 下一步动作及承诺完成时间 |
| 6 | 计划开始时间 | 15 | 交付成果或完成凭证 |
| 7 | 计划完成时间 | 16 | AI定制交付成果说明 |
| 8 | 我方负责人 | 17 | AI提取依据（合同条款来源） |
| 9 | 客户责任人 | 18 | 人工复核状态 |

### 2.4 AI 配置（侧边栏面板）

- 预设服务商一键切换：**DeepSeek（默认）** / 通义千问 / OpenAI，也支持自定义 OpenAI-compatible 端点
- API Key 保存在后端 `.ai_config.json`（不进前端、不进 Git），前端仅显示脱敏 Key（前 4 位 + 后 4 位）
- 内置"测试连接"按钮，保存即生效，无需重启
- 未配置 Key 时自动使用规则解析模式，基础功能完整可用

### 2.5 运行模式

| 模式 | 说明 | 适用 |
|------|------|------|
| rule（默认） | 规则解析，正则/关键词从合同提取真实字段，无需 API Key | 日常使用、无 Key 环境 |
| llm_enhanced | 规则优先 + LLM 增强，配置 Key 后自动切换 | 追求更高识别/拆分质量 |
| mock | 预设演示数据 | 仅演示，禁止用于真实合同 |

## 三、产品说明书（使用流程）

### 3.1 启动应用

```bash
chmod +x start.sh && ./start.sh
```

启动后访问前端 http://127.0.0.1:3131 ，后端 API http://127.0.0.1:8000 ，接口文档 http://127.0.0.1:8000/docs 。

### 3.2 配置 AI（可选，推荐）

1. 点击左侧边栏"AI 配置"打开配置面板；
2. 选择预设（DeepSeek 推荐）或自定义端点；
3. 粘贴 API Key（DeepSeek Key 在 https://platform.deepseek.com 获取）；
4. 点击"测试连接"确认可用后保存。暂不配置也可使用规则模式完成全流程。

### 3.3 标准操作流程（9 步）

1. **资料上传**：点击上传卡片选择 `.docx`/`.doc` 文件；为每个文件确认类型（合同 contract / 服务计划 plan）；系统对类型存疑时会显示警告但尊重你的选择。**至少上传一份合同**，否则"AI 全流程分析"按钮会被拦截。
2. **AI 全流程分析**：点击按钮启动 9 步管线；在进度面板中观察每步状态，必要时可暂停/跳过/重试。全部完成后自动进入识别结果页。
3. **识别结果确认**：核对合同核心信息（甲乙方、项目名称、费用、服务期限、驻场安排、响应时效），展开"识别依据"核对每个字段出自合同哪一条。发现合同与服务计划冲突时，查看交叉核验结论。
4. **澄清追问**：对系统生成的追问逐条作答（如签署日期、责任人、争议口径）。允许先留空提交让流程继续，后续再补充。
5. **任务复核**：在任务主表中逐条检查 18 字段；可直接行内编辑、新增、删除任务；查看颗粒度检查、待确认清单与风险提示并处理；点击"报告校验"确认 9 项规则全部通过。
6. **AI 交付成果**：在任务复核页的交付成果面板中，按任务或整单生成交付文档，可下载单个文件或打包下载，也可将成果保存为模板复用。
7. **版本记录**：复核完成后保存一个版本（版本名建议含日期）；后续如改坏可一键回退。
8. **导出报告**：导出 CSV 任务表（可直接导入 Excel/项目管理工具）、Markdown 项目报告或完整数据包。
9. **最小验收建议**（新环境首次使用）：上传一份测试合同 → 跑通全流程 → 保存并删除一个版本 → 确认页面刷新正常。

### 3.4 使用红线（系统强制约束）

- 真实合同模式下不使用 Mock 数据；
- 合同签署日期为空时系统不会虚构日期；
- 只上传合同时，任务不会引用不存在的服务计划；
- 报告导出前必须通过 9 项校验；
- 每条任务的"AI提取依据"必须指向合同条款。

## 四、部署指南

### 4.1 环境要求

| 依赖 | 版本 | 检查命令 |
|------|------|----------|
| Python | ≥ 3.10 | `python3 --version` |
| Node.js | ≥ 18 | `node --version` |
| npm | 随 Node | `npm --version` |

支持 macOS / Windows / Linux（启动脚本 `start.sh` 为 bash，Windows 建议在 Git Bash/WSL 中运行，或按 4.3 手动启动）。

### 4.2 获取代码

```bash
# 方式一：克隆（推荐）
git clone https://github.com/bruceleeu-creator/He-Tongchaifen.git
cd He-Tongchaifen

# 方式二：已有目录（首次推送/拉取见 GIT_推送拉取指南.md）
```

### 4.3 安装与启动

**方式一：一键脚本（推荐，macOS/Linux）**

```bash
chmod +x start.sh && ./start.sh
```

脚本自动完成：创建 `.env` → 创建 Python 虚拟环境 → 安装后端依赖 → 安装前端依赖 → 启动前后端。

**方式二：手动安装**

```bash
# 后端
cd api
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# 前端（另开终端）
cd app
npm install
```

启动：

```bash
# 后端（在 api/ 下，venv 已激活）
python -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload

# 前端（在 app/ 下）
npm run dev    # 默认 http://127.0.0.1:3131，/api 自动代理到 8000
```

### 4.4 配置文件

**AI 配置（可选）**：

```bash
cp .ai_config.example.json .ai_config.json
```

编辑 `.ai_config.json`，把占位文本替换为真实 API Key：

```json
{
  "preset": "deepseek",
  "api_key": "sk-你的真实Key",
  "base_url": "https://api.deepseek.com/v1",
  "model": "deepseek-chat",
  "temperature": 0.1,
  "timeout": 120
}
```

也可以启动后在前端侧边栏 AI 配置面板中直接配置（推荐，保存即生效）。

**环境变量（可选）**：`start.sh` 会自动从 `.env.example` 创建 `.env`，默认 `RUN_MODE=rule`、`PARSER_MODE=auto`，一般无需修改。

### 4.5 访问地址汇总

| 服务 | 地址 |
|------|------|
| 前端 | http://127.0.0.1:3131 |
| 后端 API | http://127.0.0.1:8000 |
| API 文档（Swagger） | http://127.0.0.1:8000/docs |
| API 文档（ReDoc） | http://127.0.0.1:8000/redoc |
| 健康检查 | http://127.0.0.1:8000/health |

### 4.6 数据说明与迁移

- 运行数据按运行实例存放在 `runs/{run_id}/`（任务表、识别结果、版本历史等 JSON），上传原件在 `uploads/`，导出在 `exports/`，解析缓存在 `parsed/`
- 这些目录**已 gitignore，不会随 Git 同步**；换电脑需要迁移历史数据时，手工拷贝这四个目录（⚠️ 其中含客户合同等敏感资料，拷贝前确认合规）
- API Key 存于 `.ai_config.json` / `.env`，同样不入库，新机器需重新配置

### 4.7 常见问题

| 现象 | 处理 |
|------|------|
| 端口被占用（3131/8000） | 关闭旧服务窗口后重新 `./start.sh`；或 `lsof -ti:8000 \| xargs kill -9` 释放端口 |
| 前端启动失败 | `cd app && rm -rf node_modules && npm install` 重装依赖；确认 Node ≥ 18 |
| 后端启动失败 | 确认 venv 已激活且依赖已装：`cd api && source venv/bin/activate && pip install -r requirements.txt` |
| Python 环境冲突（PYTHONHOME） | 用 `start.sh` 启动（已做 `env -u PYTHONHOME` 处理），或手动 `env -u PYTHONHOME -u PYTHONPATH python3 ...` |
| AI 连接失败 | 检查 `.ai_config.json` 的 api_key / base_url / model；用侧边栏"测试连接"验证；无 Key 时系统自动降级规则模式，不影响基础流程 |
| 上传后识别不到文件 | 确认文件为 `.docx`/`.doc`；确认合同/计划类型选择正确；重新上传后再跑全流程 |
| 全流程提示"找不到合同文件" | 检查是否只上传了 plan 类型文件；至少上传一份 contract 类型文件 |
